# План

Стек: существующие статические HTML/CSS/JS, Playwright и node:test. Без новых зависимостей и API.

1. Сначала регрессионные browser-сценарии записи и контекста консультации.
2. Общий booking UI сообщает доступность и предлагает прямой контакт, сохраняя безопасную серверную запись; main обрабатывает контекст консультации.
3. Главная: условия групповой теории, два основных входа, компактная ссылка WhatsApp; партнеры после контактов. CSS текущего проекта.
4. Обновление версий всех измененных ресурсов и их импортов.
5. Node и browser проверки, CUA desktop/mobile, независимое ревью логики, diff, статус проекта.

Распределение: помощник меняет js/booking-form.js, js/main.js, js/groups.js и tests/browser/group-booking.spec.js. Основной агент меняет HTML/CSS, tests/browser/site.spec.js, версии потребителей и документацию. Не пересекать запись файлов.

Ограничение: backend booking_unconfigured остается отдельным этапом настройки. Готовый fallback обеспечивает прямое обращение в школу, но не означает работающую онлайн-запись.

## Результат, 2026-10-05

Первый этап UX готов локально по specs/011-home-entry-ux: условия теории и два входа на первом экране; партнерский раздел после контактов; при недоступном расписании и CAPTCHA доступны WhatsApp и телефон; консультации из тренировки/экзамена не требуют группы. При восстановлении расписания доступна штатная запись.

Проверено: 97 Node, 206 bot и typecheck, 140 Python tools, 63 Playwright на 1280/390/320 px. CUA: первый экран desktop/mobile, fallback и мобильная консультация. Независимое ревью завершено без открытых замечаний; git diff --check прошел.

Production booking_unconfigured остается отдельным блокером. Реальные заявки не отправлялись, рост конверсии не измерен. Commit, push и deploy не выполнялись.
