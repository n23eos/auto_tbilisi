# Проверка реализации и выпуска

Это будущий протокол приемки. Код функции еще не реализован; перечисленные новые файлы/fixtures появятся по tasks.md. Текущий этап проверяет только документы.

## Подготовка

Отдельные локальная/staging D1, тестовый Telegram-бот и сотрудник, тестовая Access-конфигурация, синтетические телефоны. Реальные заявки/уведомления не использовать. Проверить manifest/lockfile, существующие npm-зависимости и .venv. Не импортировать пользовательские backup в тесты UI.

Из корня проекта после реализации:

```sh
npm test
npm run test:browser
.venv/bin/python -m pytest tools chat_agent/tests -q
```

Из bot/:

```sh
npm test
npm run typecheck
npx wrangler d1 migrations apply avtoshkola-bot --local
npx wrangler dev --local --port 8787
```

Имя local D1 сверить с wrangler.toml перед вызовом. `--remote` не использовать в локальной проверке. Главная: `python3 -m http.server 8765`. Browser fixtures направляют API в локальный Worker; production URL не подменяется коммитом ради тестов. Worker admin assets и auth проверяются отдельным staging окружением; local test-only verifier не должен попадать в production.

## Сценарии и ожидаемые результаты

1. US1: freeze time=2026-09-12 Asia/Tbilisi. Создать 21.09/05.10/19.10 в 19:00; статус planned. Advance до 22.09: осталось две будущих, новая сама не появляется. Move 05.10 ->12.10, scope following: 12.10/26.10, те же IDs. Append:09.11. Четвертая будущая отвергается.
2. Конфликт: следующая confirmed, две одновременные правки schedule revision, collision, дата в прошлом, неверный день февраля. В каждом случае нет частичных изменений групп/audit/outbox. Отдельно сдвиг 05.10/19.10 на +14 дней ->19.10/02.11 и обратный перенос без промежуточной unique collision.
3. US2: сохранить перенос, получить одинаковые IDs/revisions/dates с сайта/TG/Python. Уже открытая страница <=60s. Отключить Worker: сообщение unavailable, запись отключена. Отключить Python/LLM: сайт и TG продолжают запись.
4. US3: три канала, три разные тестовые заявки, выбранная группа сохранена. Повторить каждую отправку 10 раз: один reference. Обрыв после commit до ответа: retry дает тот же reference. Изменить group revision во время анкеты: повторное согласие. Одновременно с POST закрыть/отменить/перенести группу: admission guard не допускает запись на старое состояние. Телефон не попадает в LLM transport, analytics и журналы.
5. US4: 11 confirmed при capacity12, 20 конкурирующих confirm: ровно один новый confirmed. Снижение capacity до11 отвергается. Transfer на полную группу оставляет прежнюю запись целиком. Cancel группы сохраняет историю и уведомления.
6. US5: crash до inbox insert, после insert, после domain batch, после Telegram send до отметки sent. Проверить retry/lease, отсутствие дублей booking, допустимость повторного сообщения и видимость failed. Просроченный lease не может перезаписать результат нового исполнителя. Два события одного чата не теряют шаг анкеты; поздний update не обгоняет ранний с будущим retry_at. Prompt до booking доставляется по session ref, смена шага отменяет старый prompt. Перенос с тремя учениками создает три уведомления; старое confirmed после cancelled не отправляется.
7. Security: anonymous admin, JWT с неверными подписью/iss/aud/exp/email, прямой workers.dev, Origin/CSRF, чужой TG actor/chat, spoof student_chat_id/status. Ни один запрос не меняет данные и не возвращает PII.
8. Retention: границы 24h,7d,30d,90d,180d; old terminal_at не сдвигается. Inbox/анкеты/очереди/индексы не сохраняют удаленный контакт. Повтор cron безопасен. Контакт не копируется в staff Telegram.
9. UI CUA: 320/390/1280 px, клавиатура/фокус, календарь, preview переноса, конфликт без потери ввода, формы трех каналов, пустой/полный/недоступный список, manual-contact. Время create<=60s/move<=30s измерить после входа.
10. Recovery: изолированная копия backup/Time Travel, сравнить groups/bookings/IDs/counts, выполнить cleanup до открытия, outbox остановлен до сверки. Измерить RTO<=60m и возраст backup<=24h. Production восстановление этим тестом не разрешается.

## Release gates

- SC-001..006 подтверждены отчетом; вся обязательная матрица PASS.
- Реальные Worker/D1/hostname/Access проверены; нет placeholder в действующей конфигурации.
- Backup и restore проверены, секреты не попали в Git, cron доступен.
- Старые редакторы дат отключены, legacy заявки доступны, все три читателя используют один источник.
- Cutover без двойной отправки FormSubmit+Worker. Тестовая доставка проверена отдельно от живого smoke.
- Измененные CSS/JS версии согласованы по проекту, сгенерированная KB совпадает с исходниками.
- Публикация и отправка реальным ученикам только по разрешению владельца.
