# Архитектурные решения, 2026-09-29

## Проверенный исходный код

- bot/src/facts.ts и router.ts: свободный текст next_group_date, отдельная кнопка меню, нет group_id у leads.
- bot/src/index.ts: событие отмечается до routeUpdate, после ошибки 200. Для надежного приема нужно исправление.
- bot/src/leads.ts: бизнес-переходы и audit сейчас отдельные запросы.
- bot/src/cleanup.ts: 90 дней после closed по updated_at, абсолютный предел 180 дней; расширение должно охватить все новые копии PII.
- chat_agent/facts.py: одна группа на service_id, статус и date, история/revision. Уже есть полезный образец optimistic locking.
- chat_agent/static/admin.js: редактор даты существует; production доступ не проверен.
- chat_agent/http_app.py: публичный catalog отдает цены, не список групп.
- index.html: раздел ближайших групп отсутствует; js/main.js отправляет форму FormSubmit.
- bot/wrangler.toml: placeholder D1 ID. Наличие кода не подтверждает действующего бота.
- База знаний запрещает называть дату, старые specs/001 запрещают анкету в чате. Новое требование заменяет эти ограничения для групповой теории.

## ADR-01: общий источник

Decision: D1 в существующем Worker владеет группами, записями и техническими очередями. Python читает группы, не хранит копию.
Rationale: запись и даты работают без VPS/AI, в Telegram нет дополнительного сетевого перехода к Python; одна точка записи и транзакции.
Alternatives: canonical SQLite Python дешевле по reuse готовой админки, но делает все каналы зависимыми от VPS, резервирования и отдельной доставки. Синхронизация D1/SQLite создает конфликт владельцев. Новая внешняя CRM увеличивает число компонентов. Эти варианты не выбраны.

## ADR-02: один административный интерфейс групп

Decision: Worker отдает мобильную админку групп и записей, Access проверяется в origin. Используем существующий простой HTML/CSS подход. Python-редактор групп закрывается и ведет сюда.
Rationale: управление не требует доступности AI/VPS и проксирования привилегированных запросов. Цены не переносим в рамках этой функции.
Alternatives: Python UI + server proxy уменьшает перенос UI, но добавляет credential и второй сервер в цепочку управления; Telegram как единственное управление неудобен для списка и предпросмотра.

## ADR-03: ограниченное расписание

Decision: реальные группы со стабильными IDs, максимум три будущие. Генерация при создании/кнопке добавления, интервал 14 дней. Перенос меняет существующие IDs; preview защищен revision.
Rationale: плавающее вычисление дат при каждом запросе теряет связь с заявками; безусловный rolling horizon публикует необсужденные наборы.
Alternatives: бесконечная recurrence, AI-команда изменения, отдельный календарный сервис не нужны в v1.

## ADR-04: надежность

Decision: durable inbox/outbox на той же D1, атомарные доменные команды с replay результата. Доставка at-least-once с возможным повтором при неоднозначном ответе Telegram.
Rationale: прием пользователя и доставка сотруднику имеют разные границы отказа. Успешный прием не может зависеть от отправки в Telegram.
Alternatives: только ручной /resend или in-memory retry теряют работу при остановке процесса; внешний queue broker пока избыточен.

## ADR-05: минимум данных

Decision: контакт внутри записи, без master customers и автоматического merge по телефону. В выделенной форме чата PII обходят LLM. Web-клиенты без связанного Telegram получают задачу звонка.
Rationale: проще сроки удаления, нет ошибочного объединения семейных телефонов и притворной проверки личности. Привязка Telegram, SMS, оплата могут стать отдельными функциями.

## Документация

Context7 запрошен, но вернул Monthly quota exceeded. Проверены официальные первоисточники 2026-09-29:
- [D1 batch](https://developers.cloudflare.com/d1/worker-api/d1-database/): SQL statements batch транзакционны, ошибка откатывает последовательность. Нулевой affected rows не является ошибкой; выбран явный guard.
- [Access JWT](https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/authorization-cookie/validating-json/): origin должен проверять токен, а не доверять заголовку email.
- [Telegram webhook](https://core.telegram.org/bots/api#setwebhook): секрет заголовка, повтор доставки и max_connections. Собственная durable обработка не должна полагаться на бесконечные повторы Telegram.
- [D1 recovery](https://developers.cloudflare.com/d1/reference/time-travel/): Time Travel и ограничения по плану. Цели восстановления проекта требуют отдельной репетиции.

Версии зависимостей зафиксированы по manifest в plan.md; облачные API не имеют версии пакета проекта. Lockfile и доступность Access/тарифа проверяются при реализации. Инфраструктурные неизвестные вынесены в release gates, архитектурных развилок не оставлено.
