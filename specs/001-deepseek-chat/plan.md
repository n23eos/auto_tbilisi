## Решения и структура

Python 3.12+ backend в chat_agent/ с agent/, tools/, data/, tests/, evals/, README.md. Доменная логика на стандартной библиотеке, pytest; HTTP-слой и версии зависимостей выбираются после проверки документации. API модели скрыт за интерфейсом с offline fixtures.

Виджет: js/chat-logic.js, js/chat.js, css/chat.css; без сборщика. Backend размещается отдельно от GitHub Pages. Production hosting пока не выбран, локальную реализацию это не блокирует.

Поток: HTTP validation → harness → DeepSeek tool selection → typed tools → structured draft → validator → deterministic renderer → response. Trace охватывает все этапы. Первым реализуется сквозной сценарий цены, затем расписание и комбинации.

Перед API-интеграцией: актуальная документация DeepSeek через Context7, при недостаточности — официальный источник. Фиксировать модель, версии и API-контракт. Ключ не передавать в текст переписки. Live-вызовы требуют разрешённых расходов.

## Изоляция и проверки

Offline tests/evals без сети и production-данных. Fixture-цены не считаются текущим прайсом. Отдельное Python-окружение изолирует зависимости, но не является security sandbox; Git branch не ограничивает сеть/секреты. Откат: отключение виджета и отдельного сервиса, без миграции существующего бота.

Конституция соблюдена на уровне решения; runtime ещё не реализован. Проверки первого этапа — структура файлов и diff. При реализации — pytest/evals, проверки проекта по CLAUDE.md, UI через CUA на desktop/320px.

Метрики с явными знаменателями: success_rate и human_escalation_rate (покрытие запросов); eval_pass_rate (регрессии); unsupported_claim_rate (отклонённые утверждения, не универсальная «частота галлюцинаций»); tool_error_rate (источники); retry_rate (качество схем/prompt); latency и usage/cost (выбор лимитов/модели). Нет данных — не заявлять измеренный результат.

Демо и объяснения: docs/chat-harness-demo.md. Контракты и data-model оформляются вместе с первым срезом. Дополнительные архитектурные фреймворки не нужны.
