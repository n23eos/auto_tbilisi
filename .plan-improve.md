# План улучшения проекта: что сделано и что осталось

Дата: 2026-09-01. Основа — аудит безопасности бота и аудит доступности
и производительности сайта, проведённые в этой сессии.

## Сделано

### Спринт 1 — фундамент

- **CI.** `.github/workflows/ci.yml` — три независимые job'ы: сайт (30
  тестов), бот (141 тест + typecheck), Python-инструменты (126 тестов).
  До этого всё гонялось только руками.
- **CHECK на статусы заявки.** Миграция `0002_leads_status_check.sql`
  пересобирает `leads` с ограничениями на `status` и `delivery_status`.
- **Чистка журнала.** `lead_events` рос без ограничения — теперь 180 дней.
- **Зависимости.** wrangler 3 → 4.127, vitest 2 → 4.1, пакет
  `@cloudflare/vitest-pool-workers` переименован в `@cloudflare/vitest-plugin`.
  12 уязвимостей → 0. Заодно закрыто расхождение `compatibility_date`.
  Побочный эффект бампа: изоляция хранилища теперь на файл тестов, а не на
  тест, — чистка таблиц перенесена в `beforeEach`.

### Спринт 2 — безопасность и прод-готовность

- **Таймауты** на вызовы Telegram API (10 с) и на отправку формы заявки
  в FormSubmit (15 с). Без них зависший запрос держал воркер до предела
  и оставлял кнопку заблокированной навсегда.
- **Оповещение о падениях** в чат админов, с паузой в 5 минут.
- **Утечка токена в логи** — вычистка токена из текста ошибок.
- **Поток заявок** — потолок 3 заявки с чата за сутки, `/resend` пачками
  по 25 с явным остатком.
- **Персональные данные** — уборка затирает имя, вопрос и chat_id, а не
  только телефон.
- **Тихо сломанный деплой** — без `ADMIN_CHAT_ID`/`ADMIN_IDS` бот теперь
  отвечает 404, а не принимает заявки в никуда.
- Мелочи: `parseLeadId` на callback_data, `Object.hasOwn` на словарях.

### Спринт 3 — SEO и скорость

SEO оказался в основном уже сделан (LLMO-проход от 2026-08-31): полные
метатеги, JSON-LD с DrivingSchool, Course, FAQPage, BreadcrumbList.
Добавлено:

- `og:image:width/height/alt` на страницы билетов, тренировки, вопросов;
- **даты считаются из git**, а не пишутся литералом — `tools/update_sitemap.py`
  и `content_date()` в `build_llms_full.py`;
- **видео шапки не качается до решения о нём** — при `autoplay` браузер
  игнорировал `preload="metadata"` и тянул 1,6 МБ в окне LCP;
- `preload as=fetch` для `tickets-b-ru.json` — запрос уходил только после
  трёх последовательных раундтрипов за модулями.

### Спринт 4 — доступность тренажёров

- Контраст границ кнопок ответа и фильтров: было 2,16:1, WCAG требует 3:1.
- Правильный ответ передавался одним цветом — добавлены подписи для
  скринридера (`.sr-only`), разметка вынесена в общий `js/answer-marking.js`
  (была скопирована в два файла слово в слово).
- Экран результатов терял фокус; предупреждение об истекающем времени было
  только красным цветом.
- `aria-pressed` на фильтрах, `aria-invalid`/`aria-describedby` на форме,
  `preventDefault` на стрелках, `prefers-reduced-motion` для `exam.css`.
- Скачки вёрстки: у картинок билетов не было размеров, каждый вопрос сдвигал
  варианты ответа вниз.

### Спринт 6 — систематизация

- `CLAUDE.md` — стек, команды, границы модулей, неочевидные правила.
- README корня и бота обновлены под новое поведение.

## Осталось — требует решения владельца

| Пункт | Почему не сделано |
|---|---|
| **Описания к картинкам билетов** | 524 картинки, и для вопросов про дорожную ситуацию картинка *и есть* вопрос. Сейчас у всех один alt «Изображение к вопросу билета». Незрячий ученик такие билеты решать не может. Дёшево не чинится — нужен либо ручной труд, либо генерация с проверкой |
| **Анимация заголовка держит LCP** | `.marquee__inner` выезжает из-под обрезки 700 мс, и до конца анимации LCP не засчитывается. Это ядро визуального решения страницы — менять без вас не стал |
| **Экзамен качает 682 КБ ради 30 билетов** | Кнопка старта ждёт весь `tickets-b-ru.json` (92 КБ в gzip). Чинится разбиением данных — это переделка формата, а не правка |
| **Группа админов = доступ к персональным данным** | `ADMIN_IDS` определяет, кто может *нажимать*, но карточки видит любой участник группы, включая всю переписку выше. Решается отключением ссылки-приглашения, а не кодом |
| **Команда «забудь меня»** | Ученик не может удалить свои данные по запросу. Шесть строк кода, но это продуктовое решение |
| **Шесть начертаний шрифтов** | Грузятся три веса Unbounded и три Golos, странице видимо нужно меньше. Убирать лишние — визуальное решение |
| **Архив планов** | `.plan-*.md` в корне: пять файлов, часть выполнена. Переносить в `docs/plans/` не стал — вы на них ссылаетесь |

## Правило работы

Каждый пункт: тест → правка → все три набора тестов → коммит.
