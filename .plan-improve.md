# План улучшения проекта: спринты + скиллы

Дата: 2026-09-01. Основа — итоги аудита (`.plan-audit-fixes.md`): критичные пункты
закрыты, остались отложенные решения плюс системные улучшения.

Проект: сайт avtoshkola.ge (GitHub Pages) + тренажёры билетов + Telegram-бот
(Cloudflare Workers + D1) + Python-инструменты + база знаний.

## Подобранные скиллы (все уже установлены локально)

| Скилл | Для чего в этом проекте |
|---|---|
| `verification-loop` | Единый quality gate перед каждым коммитом: тесты, typecheck, secret scan |
| `security-review` / `security-scan` | Вебхук бота, форма звонка, D1-запросы |
| `prod-readiness-audit` | 25 пунктов «что сломается на 500 пользователях» — у бота и формы публичная поверхность |
| `seo` | Автошкола живёт с поиска: schema.org (LocalBusiness, FAQPage), метатеги, sitemap |
| `web-perf` | Core Web Vitals: лендинг с анимациями + сотни webp-картинок билетов |
| `accessibility` | WCAG для тренажёра и экзамена — там реальные пользователи учатся |
| `browser-qa` | Автоматическая проверка UI экзамена/тренировки после правок |
| `workers-best-practices`, `wrangler`, `cloudflare` | Бот: мажорный бамп wrangler (B8/B9), лимиты Workers, cron cleanup |
| `canary-watch` | Слежение за прод-URL после деплоев |
| `hallmark` | Дизайн-аудит страниц (уже использовался — есть `.hallmark/log.json`) |
| `knowledge-ops` | Порядок в `baza-znaniy/`: синхронизация .md → dlya-bota, дедупликация |
| `codebase-onboarding` + `doc-updater` | CLAUDE.md проекта, актуализация README |
| `code-review` (`/code-review`) | После каждого спринта |
| `blueprint` | Если спринт разрастётся в многосессионную работу |

Маркетплейс skillsmp проверен — по темам «telegram bot / static site audit»
ничего лучше локального набора нет.

## Спринт 1 — Фундамент: CI и хвосты аудита (≈1 сессия)

Цель: любое изменение проверяется автоматически, отложенные решения аудита закрыты.

1. GitHub Actions: на PR/push гонять `npm test` (сайт), `bot: test + typecheck`,
   Python-тесты tools → verify: зелёный прогон в Actions.
2. Решить **Ж4b**: `CHECK` на `leads.status` через пересборку таблицы в новой
   миграции (SQLite-паттерн: create → copy → drop → rename) → verify: `schema.test.ts`.
3. Решить **О8a**: срок хранения `lead_events` (предложение: 90 дней) →
   чистка в `runCleanup` → verify: тест cleanup.
4. **B8/B9**: мажорный бамп wrangler + vitest, свериться `workers-best-practices` →
   verify: 0 уязвимостей высокой серьёзности, тесты зелёные.

Скиллы: `verification-loop`, `wrangler`, `workers-best-practices`, `code-review`.

Каждый спринт: план пункта → тест → правка → `verification-loop` → `/code-review`
→ коммит. Спринты 1–2 первыми: без CI и безопасности остальное строить рискованно.
Спринты 3–4 можно параллелить с 5.
