# Проверка корректности билетов и ответов — план

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development или superpowers:executing-plans.

**Goal:** Понять, можно ли доверять базе: совпадают ли вопросы, ответы и пометка правильного ответа с независимыми источниками, и где в базе дефекты.

**Что уже сделано (структурная проверка, результаты ниже в разделе «Итог шага 0»):** база проверена на внутренние противоречия — их нет.

**Tech Stack:** Python + pymupdf (чтение PDF), requests + BeautifulSoup (повторная выборка с сайта).

---

## Три независимых угла проверки

Одна проверка ничего не докажет: парсер, сверенный сам с собой, всегда прав. Поэтому три разных источника истины.

| Угол | Что проверяет | Чего НЕ проверяет |
|---|---|---|
| A. Официальный PDF `RU-B.pdf` | Правильный ответ по независимо сгенерированному документу | PDF от 22.12.2014 — билеты могли измениться |
| B. Повторная выборка отдельных страниц билетов | Не соврал ли парсер относительно текущего сайта | Ошибки самого источника |
| C. Смысловая проверка выборки | Ошибки самого источника (неверный ответ по ПДД) | Не даёт гарантии — это мнение, а не факт |

Ни один угол не является полным. Вывод строится из их пересечения.

Структура PDF (проверено вручную на страницах 3-4):

- дальше блоки текста: сам вопрос, тексты ответов в двух колонках (x≈73 и x≈346), затем пояснение по-грузински (начинается с `განმარტება`);
- на одной странице может быть несколько вопросов;

- [ ] **Step 1: Тест на разбор одного вопроса из PDF**

Тест работает не на живом PDF, а на заранее сохранённом списке блоков (координаты + текст) — фикстура в самом тесте. Так тест не зависит от 78-мегабайтного файла.

```python
BLOCKS = [
    (28.4, 68.6, "ВОПРОС 1 ПРАВИЛЬНЫЙ ОТВЕТ: 2"),
    (47.6, 309.2, "1 2"),
    (47.6, 365.2, "3"),
    (53.5, 232.6, "Из данных опознавательных знаков, который является «Различающим знаком»"),
    (73.2, 302.9, "I"),
    (346.8, 302.9, "II"),
    (73.2, 358.9, "III"),
    (255.1, 424.1, "განმარტება: пояснение"),
]


def test_parse_pdf_question_reads_number_and_correct():
    question = audit.parse_pdf_blocks(BLOCKS)[0]
    assert question["number"] == 1
    assert question["correct"] == 1  # в PDF нумерация с единицы, у нас с нуля


def test_parse_pdf_question_orders_answers_by_position():
    question = audit.parse_pdf_blocks(BLOCKS)[0]
    assert question["answers"] == ["I", "II", "III"]


def test_parse_pdf_question_drops_georgian_explanation():
    question = audit.parse_pdf_blocks(BLOCKS)[0]
    assert all("განმარტება" not in a for a in question["answers"])
    assert "განმარტება" not in question["question"]
```

- [ ] **Step 3: Реализовать разбор**

`tools/audit_tickets.py`: функция `parse_pdf_blocks(blocks)` разбирает блоки одной страницы в список вопросов.
Правила разбора:
- блок с `ВОПРОС\s+(\d+)` и `ПРАВИЛЬНЫЙ ОТВЕТ:\s*(\d+)` открывает новый вопрос;
- блоки ниже заголовка и до следующего заголовка относятся к этому вопросу;
- ответы — блоки, начинающиеся в колонках ответов (x0 в пределах ±5 от 73.2 или 346.8), порядок — сортировка по (y, x);
- вопрос — оставшиеся кириллические блоки выше первого ответа;
- блоки с грузинскими буквами (`Ⴀ-ჿ`) отбрасываются как пояснение;
- блоки-номера в колонке x≈47.6 отбрасываются.

- [ ] **Step 4: Проверить разбор на реальном PDF и оценить его качество**

Ключевой шаг: сначала убеждаемся, что разбор PDF вообще работает, и только потом делаем из него выводы.

```bash
.venv/bin/python -m tools.audit_tickets --pdf <путь>/RU-B.pdf --check-parse
```
Скрипт печатает: сколько вопросов найдено, у скольких есть номер, правильный ответ, непустой текст и ≥2 ответа. Если доля разобранных ниже 95% — разбор чинить, выводы делать рано.

- [ ] **Step 5: Сверка с базой**

Сопоставление НЕ по номеру билета (за 11 лет нумерация могла измениться), а по нормализованному тексту вопроса и набору ответов.

Нормализация: нижний регистр, схлопнутые пробелы, убраны `ё`→`е`, кавычки-ёлочки и дефисы приведены к общему виду, отброшены концевые знаки препинания.

Три корзины на выходе:
1. **совпало и правильный ответ тот же** — билет подтверждён независимым источником;
2. **совпало, но правильный ответ разный** — требует ручного разбора: либо ошибка парсера, либо билет изменили после 2014;
3. **в PDF не найдено** — новые или переформулированные билеты, PDF о них ничего не говорит.

- [ ] **Step 6: Отчёт**

`.venv/bin/python -m tools.audit_tickets --pdf ... --report` печатает сводку по трём корзинам и полный список из корзины 2 с обеими версиями (номер билета, вопрос, наш ответ, ответ из PDF).
