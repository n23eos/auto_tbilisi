# База билетов ПДД (Грузия, категория B/B1, русский язык)

Дата: 2026-08-26
Ветка: `dev`
Статус: согласовано (ревизия 2)

## Цель

Получить машинно-читаемую базу всех актуальных экзаменационных билетов ПДД Грузии
(категория B/B1, русская локализация) с картинками, чтобы позже сделать на сайте
раздел-тренажёр. **Сайт (`index.html`, css, js) на этом этапе не трогаем.**

## Источник

`https://teoria.on.ge` — публичный каталог официальных экзаменационных билетов
Сервисного агентства МВД Грузии.

Разведка источника (проверено вручную):

- Список билетов категории B/B1: `https://teoria.on.ge/tickets/2?page=N`, по 20 билетов на страницу.
- Всего билетов — в `<h1>`: `сул 921 билети` (число берём регуляркой из заголовка, не хардкодим).
  921 билет = 47 страниц, на последней ровно один билет.
- Число страниц — из `<select class="paginator-select">`, максимальное `<option value="N">`.
- Язык переключается cookie `exam-settings` (JSON, URL-encoded). Работает только полный объект:
  `{"category":2,"locale":"ru","skin":"dark","user":0}`. Неполный объект локаль не переключает.
- Признак применённой локали в HTML: у `<article>` есть класс `locale-ru`.
- Один билет = `<article class="ticket-container ...">`, внутри:
  - `<div class="t-num">#1</div>` — id билета (совпадает с `?ticket=1` в ссылке), нумерация с пропусками
  - `<p class="t-question-inner">` → `<span class="text-wrap">` — текст вопроса
  - `<figure class="t-image"><img src="...">` — картинка, необязательна
  - `<p class="t-answer t-answer-N">` → `<span class="t-a-text">` → `<span class="text-wrap">` — вариант ответа
  - пустые слоты помечены классом `ans-empty` — пропускаем
  - правильный ответ помечен атрибутом `data-is-correct-list="true"` на `<p class="t-answer ...">`
- Пояснения к билетам у источника только на грузинском — в базу не тянем.

## Область работы

Скрипт жёстко ограничен категорией `2` (B/B1) и локалью `ru`. Обе величины —
именованные константы в начале файла (`CATEGORY_ID = 2`, `LOCALE = "ru"`,
`CATEGORY_LABELS = ["B", "B1"]`), из них выводятся URL, cookie, имя JSON и путь к картинкам.
CLI-параметров для категории и языка нет: сейчас они не нужны, а «наполовину
параметризованный» скрипт даёт ложное ощущение универсальности при захардкоженных путях.
Расширение на другие категории — отдельная задача, там же понадобится дедупликация
между категориями.

```
tools/
  parse_tickets.py         # парсер
  requirements.txt         # requests, beautifulsoup4
  requirements-dev.txt     # -r requirements.txt + pytest
  tests/
    fixtures/tickets-page-ru.html
    test_parse_tickets.py
  .cache/                  # в .gitignore, в git не попадает
data/
  tickets-b-ru.json        # результат
  tickets/images/*.jpg     # картинки билетов
```

### Формат данных

```json
{
  "meta": {
    "category_id": 2,
    "categories": ["B", "B1"],
    "lang": "ru",
    "source": "https://teoria.on.ge/tickets/2",
    "parsed_at": "2026-08-26T14:31:07+04:00",
    "total": 921
  },
  "tickets": [
    {
      "id": 1,
      "question": "У водителя какого автомобиля появляется обязательство уступить дорогу?",
      "image": "tickets/images/f24b95a352dc25441ea2b32cb823623b.jpg",
      "answers": ["У водителя грузового автомобиля", "У водителя легкового автомобиля"],
      "correct": 1,
      "source": "https://teoria.on.ge/tickets?ticket=1"
    }
  ]
}
```

- `correct` — индекс правильного ответа в массиве `answers`, с нуля.
- `image` — путь относительно папки `data/`, либо `null` если картинки у билета нет.
- Имя файла картинки = имя файла у источника (хэш) — дедупликация выходит бесплатно.
- `parsed_at` — ISO 8601 с часовым поясом.
- Билеты в JSON отсортированы по `id` — чтобы повторный парсинг давал побайтово тот же файл
  и в git был читаемый diff.

### Как работает парсер

1. Ставит cookie `exam-settings` с `category=2`, `locale=ru`.
2. Качает страницу 1, читает из неё общее число билетов и число страниц.
3. Идёт по всем страницам, между запросами пауза 0.7 с, свой User-Agent
   (`autoshkola.ge tickets parser`).
4. **Кэш страниц:** `tools/.cache/category-2/ru/page-N.html`. Путь включает категорию и локаль,
   иначе русский запуск подцепит старый грузинский кэш и почти все проверки пройдут успешно.
   Перед использованием кэшированного файла проверяется, что он непустой, содержит класс
   `locale-ru` и ожидаемую категорию — иначе файл считается негодным и страница качается заново.
   Запись атомарная: пишем во временный файл рядом, потом `os.replace`. Флаг `--refresh`
   игнорирует кэш целиком. Каталог `.cache/` — в `.gitignore`.
5. Разбирает страницы через BeautifulSoup, собирает список билетов.
6. Качает картинки в `data/tickets/images/`, уже существующие файлы пропускает.
   URL картинки приводится к абсолютному через `urljoin` — источник отдаёт и `http://`,
   и протокол-относительные `//`, и относительные пути.
7. Формирует итоговые данные в памяти и **прогоняет проверки (ниже)**.
8. Только если проверки прошли — пишет временный файл и атомарно (`os.replace`) заменяет
   `data/tickets-b-ru.json`. При провале старый JSON остаётся нетронутым, скрипт завершается
   ненулевым кодом и печатает, что именно не сошлось.

### Проверки качества базы

Без них базе верить нельзя. Все — в самом скрипте, отчёт печатается в конце.
Любая непройденная проверка = база невалидна, файл не перезаписывается.

- число разобранных билетов == числу из заголовка страницы (921);
- разобрана в том числе последняя страница (на ней всего один билет — легко потерять
  и не заметить);
- каждый `id` — положительное целое, дублей `id` нет;
- ни одного пустого текста вопроса;
- у каждого билета минимум 2 ответа, ни один не пустой;
- ровно один правильный ответ на билет;
- **картинки:** у билета, у которого в HTML есть `<figure class="t-image">`, `image`
  обязан быть непустым, файл обязан существовать и быть настоящим изображением.
  `image: null` допустим только там, где картинки нет у самого источника.

### Проверка, что скачанный файл — картинка

«Файл существует и больше нуля байт» недостаточно: заглушка Cloudflare или страница
ошибки тоже весит больше нуля. Проверяем два условия:

- ответ пришёл с заголовком `Content-Type: image/*`;
- содержимое действительно декодируется как изображение (сигнатура файла + попытка
  открыть его; если в окружении есть Pillow — им, иначе проверкой магических байт
  JPEG/PNG/GIF/WebP).

Не прошло — файл не сохраняем, билет уходит в список проблемных, база невалидна.

### Обработка ошибок

- HTTP-ошибка или таймаут — 3 попытки с нарастающей паузой, потом падаем с указанием страницы.
- Билет не разобрался (нет вопроса / нет правильного ответа) — не молчим: собираем такие
  в список «проблемных», печатаем их id, база считается невалидной.
- Картинка не скачалась или оказалась не картинкой — билет в проблемные, база невалидна.

### Тесты

`tools/tests/test_parse_tickets.py` (pytest) на сохранённом куске HTML-страницы.
Сетевых запросов в тестах нет — фикстура лежит файлом.

Разбор HTML:
- билет с картинкой и 2 ответами;
- билет без картинки и с 3 ответами;
- пустые слоты `ans-empty` не попадают в `answers`;
- правильный индекс `correct`;
- билет без `data-is-correct-list` уходит в проблемные, а не молча теряется;
- `urljoin` для `http://`, `//static...` и относительного пути к картинке.

Проверки базы:
- ловит дубли `id`;
- ловит пустой вопрос;
- ловит `id`, который не положительное целое;
- ловит `image: null` у билета, у которого картинка в HTML была;
- пропускает `image: null` у билета без картинки;
- ловит недостачу билетов относительно заявленного total.

Кэш:
- кэшированный файл с чужой локалью (`locale-ka`) отбраковывается;
- пустой кэшированный файл отбраковывается.

## Чего НЕ делаем сейчас (осознанно)

- Не меняем `index.html` и стили сайта.
- Не делаем UI тренажёра — это следующий этап, отдельным спеком.
- Не парсим другие категории (A, C, D…) и другие языки.
- Не тянем грузинские пояснения к билетам.

## Правовая пометка

Сами вопросы — официальный экзамен МВД Грузии, публичные. Русский перевод, оформление
и изображения — работа on.ge. `robots.txt` источника (`Allow: /`) разрешает обход
роботом, но сам по себе не даёт лицензии на повторную публикацию перевода и картинок.

Сбор базы для внутренней работы — одно, публикация раздела на сайте — другое.
**Перед публикацией раздела на avtoshkola.ge проверить условия использования on.ge
и при необходимости запросить разрешение.** Видимая ссылка на источник желательна,
но достаточных прав сама по себе не даёт.
